## 확인할 것 (재현하지 못했거나 아직 안 본 것)

- 서버 쪽 중복 생성 방지(`Idempotency-Key`, 설계 §5): 화면은 BUG-001로 막았지만, 네트워크 재시도 같은 경우는 서버가 막아야 함.
- 느린 네트워크·오프라인에서 저장할 때의 안내.
- 저장 중 뒤로 가기.
- 시간대: 다른 시간대 사용자의 날짜 알림은 JobsIT가 확인. 화면 표시(시간대 설정 → 활동 시각)는 자동 테스트가 없음.
- 세션 점검 27묶음을 `frontend/e2e/`로 옮기기(지금은 세션 임시 폴더에만 있음).
- SSO에서 자동 테스트가 없는 것: 초대 상태 계정이 SSO로 활성이 되는 것, 로그인 실패 잠금 시간 중(`locked_until`)의 거부, SSO의 `?next=//evil.example` 같은 열린 리다이렉트, 삭제된 계정의 `no_account`.
- 그룹화·합계에서 자동 테스트가 없는 것: 사용자 정의 필드(목록·사용자·예/아니요)로 그룹화, 숫자 사용자 정의 필드의 합계, 저장된 보기를 다시 열 때 그룹을 접은 상태(지금은 기억하지 않는 것으로 보임), 휴대폰 폭에서 그룹 머리글, 작업량 열로 정렬·내보내기.
- 보드에서 자동 테스트가 없는 것: 보드 관리 권한이 없는 멤버가 빈 보드에 넣기·빼기·옮기기(403이어야 함), 참관자가 저장하지 않고 필터로 걸러 보기, 담당자·버전 보드의 + 로 만들기(담당자·버전 미리 지정), 프로젝트에 기본 유형이 꺼져 있을 때 + 로 만들기, 빈 보드에서 키보드로 카드 옮기기.
- 날짜 형식: 12시간제로 바꾼 뒤 요약 메일을 실제로 받아 시각 확인(코드는 `Dates.formatDateTime`으로 고침, DisplaySettingsIT가 형식을 확인; 메일 수신은 손으로).
- 날짜 형식: 내보내기 CSV·XLSX의 시각은 `yyyy-MM-dd HH:mm` 고정. 파일은 기계가 읽기 좋은 형식으로 두는 것이 맞는지 정할 것.
- 주 시작 토요일: 팀 플래너 1·2주 보기의 첫 열, 캘린더 월·주 보기, 날짜 선택 달력, Gantt 주 눈금이 모두 토요일에서 시작하는지 손으로 볼 것(e2e는 월요일과 날짜 선택 달력만 봄).
- 주 시작과 "이번 주" 필터: 서버와 가짜 계층 모두 주 시작 요일을 따르도록 고침(기본 일요일~토요일). 토요일 시작에서 목록 필터 결과를 화면으로 한 번 확인할 것.
- 날짜 형식을 바꾼 직후 이미 열려 있던 다른 사람의 화면: 설정은 5분 동안 다시 읽지 않고(staleTime), 다시 읽어도 이미 그린 날짜가 바로 바뀌는지는 안 봄. 새로고침 전까지 옛 형식이 남는지 볼 것. 서버 쪽 날짜(메일·활동 기록)는 인스턴스가 여럿이어도 30초 안에 따라옴(F11-D3). 실제로 인스턴스 두 개를 띄워 본 적은 없음.
- 프록시 헤더: 실제 사내 프록시(nginx)에서 사람마다 요청 제한이 따로 세지는지 확인할 것. 운영 이미지(90006c2, rootless Podman)로는 호스트에서 게시 포트로 확인함(`X-Forwarded-For` 주소 29개 → 429 없음, 주소 하나 → 21번째에 429, 앞에 가짜 주소를 붙여도 429 유지, `replica/deploy.md` "검증 기록"). 이 확인에서 Podman 네트워크(10.88·10.89)가 기본값에 없어 헤더가 무시되던 것을 찾아 90006c2에서 기본값에 넣음. Docker 192.168 풀은 여전히 `OPENPMS_TRUSTED_PROXIES`를 넣어야 함(손으로 본 적 없음).
