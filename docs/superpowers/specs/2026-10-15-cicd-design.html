1목적과 합의

작업 패키지와 개발 도구(코드 저장소·CI·배포)를 이어서, "이 일이 어느 MR/PR과 커밋으로 처리됐고, 빌드가 통과했고, 어느 환경까지 배포됐는지"를 openPMS 안에서 본다. 이어서 릴리스 관리, 이벤트에 따른 자동화까지 단계로 넓힌다(변경 관리 연결은 보류 — ITSM 제거(2026-10-16)로 기반 없음, 다시 정함). 범위 밖이던 REQ-OOS-011(GitHub·GitLab 연동과 리포지토리)을 일부 들여온다.

합의한 것

항목결정
뜻제품 기능(openPMS의 새 영역). 이 저장소 자체의 CI 파이프라인은 다루지 않음
연동 도구GitLab(자체 설치), GitHub(Enterprise·Cloud), Jenkins, Argo CD 등 배포 도구
목표추적성, 릴리스·배포 관리, 자동화를 담음(단계로 나눔). 처음 합의한 ITSM 변경 관리 연결은 ITSM 제거(2026-10-16)로 보류
받는 방식웹훅으로 바로 반영 + 주기 폴링으로 놓친 이벤트 보완. 밖에서 들어올 수 없는 도구는 폴링만
자동화프로젝트별 규칙, 기본 꺼짐. 워크플로를 지키고 연동 이름으로 기록
구조공통 이벤트 수집 계층 + 도구별 어댑터(접근안 A)
권한일반 사용자(멤버)는 보기·연결 고치기, 개발 리더는 저장소·규칙 관리, 도구 연동 등록은 전역 권한으로 위임 가능
자격 증명OPENPMS_SECRET_KEY로 AES-GCM 암호화해 저장

고른 접근: 공통 이벤트 수집 계층 + 어댑터

GitLab · GitHub · Jenkins · Argo CD→ 웹훅 / 폴링→ 어댑터
검증 · 파싱→ cicd_events
정규화 · 중복 제거→ 연결 · 릴리스 · 자동화

웹훅과 폴링 결과를 모두 정규화한 이벤트(commit·merge_request·pipeline·deployment)로 바꿔 cicd_events에 쌓는다. 새 도구는 어댑터 하나만 더한다. 같은 이벤트가 두 번 와도 (연동, delivery_key) 유일 키로 한 번만 반영한다.

버린 안: 도구별 독립 모듈(도구 4 × 목표 4로 중복), 외부 스크립트에만 맡김(서명 검증·복구가 각 팀 몫). 정형 웹훅이 약한 도구를 위해 2단계에 범용 API 어댑터를 둔다.

이름 주의. CI는 구성 항목(configuration item)으로도 읽힌다(처음에는 ITSM의 CMDB를 염두에 둔 규칙이었고, ITSM 제거 뒤에도 그대로 둔다). 이 영역의 식별자는 cicd_·pipeline·deployment, 화면 문구는 "CI/CD"·"빌드·배포"를 쓴다.

범위 밖 (1단계)

  • 파이프라인·배포 상태, Jenkins·Argo CD(2단계)
  • 릴리스 화면(3단계), 상태 자동 전환(4단계), 변경 관리 연결(5단계, 보류)
  • openPMS에서 MR/PR을 만들거나 병합하는 쓰기 동작(전 단계 범위 밖)
  • 저장소 파일 보기·코드 검색(범위 밖 유지)

사람별 권한 (기본값)

권한은 역할에 묶인다. 프로젝트 역할은 프로젝트마다 멤버에게 주고(같은 사람이 프로젝트마다 다를 수 있음), 전역 역할은 관리자가 사용자에게 준다. 역할의 권한은 관리 › 역할에서 고칠 수 있다.

들어오는 웹훅

POST /api/v1/hooks/cicd/{hookKey} — SpaConfig가 /api 밖의 주소를 index.html로 돌려주고 운영 프록시도 /api만 백엔드로 보내므로 /api 아래에 둔다. SecurityConfig에서 이 경로만 permitAll과 CSRF 제외를 건다(/api/** authenticated보다 앞에).

검증

  • GitHub: X-Hub-Signature-256(HMAC-SHA256)
  • GitLab: X-Gitlab-Token 상수 시간 비교
  • 없는 키·서명 실패는 같은 404

처리

  • 본문 1 MiB까지(넘으면 413)
  • 저장만 하고 202로 바로 답함, 처리는 cicd-process(15초)
  • delivery id(X-GitHub-Delivery·X-Gitlab-Event-UUID)로 한 번만 반영

프로젝트 경계

#123은 그 저장소가 붙은 프로젝트(와 하위 프로젝트)의 작업일 때만 연결한다. 다른 프로젝트의 작업 번호를 커밋에 적어도 연결되지 않고, 그 작업이 있는지도 드러나지 않는다. 손으로 연결할 때도 같은 검사를 한다.

저장소를 붙이는 쪽도 경계가 있다(2026-10-16, REQ-CICD-010): 연동마다 허용 프로젝트 목록이 있고, 그 프로젝트에서만 그 연동으로 저장소를 찾고 붙인다. 목록에 없으면 연동 고르기에 없고 찾기·붙이기는 꺼진 연동과 같은 404다. 목록은 시스템 관리자만 바꾸고(위임받은 연동 관리자는 볼 수 있는 프로젝트의 이름과 나머지 개수만 봄), 이 연동의 저장소가 붙은 프로젝트는 뺄 수 없다(409).

2단계에서 바뀜(2.9): 허용 프로젝트에서 빼기를 막는 것은 붙은(떼지 않은) 저장소뿐이다. 연동 삭제는 1단계의 "붙은 저장소가 있으면 409"에서 "기록이 남은 저장소(뗀 저장소 포함)가 있으면 409, 대신 끄기"로 바뀌었다(3절의 저장소 떼기).

자격 증명

  • 도구 API 토큰과 웹훅 비밀은 환경 변수 OPENPMS_SECRET_KEY(32바이트를 Base64로 적은 값, openssl rand -base64 32, 설정 키 openpms.secret-key)로 AES-GCM 암호화해 저장한다. dev 프로필은 고정된 개발용 키를 기본값으로 두고, 운영 기본값은 빈 값이라 연동 저장이 422 "암호화 키(OPENPMS_SECRET_KEY)가 설정되지 않았습니다."로 막힌다.
  • API는 끝 4자리만 돌려준다. 웹훅 비밀은 만들 때 한 번만 보여 주고, 이후에는 다시 발급만 한다.
  • 토큰은 읽기 전용 범위(GitLab read_api, GitHub contents·pull requests read)를 쓰도록 화면에서 안내한다.
  • 키 보관·백업은 운영자 매뉴얼에 적는다(키를 잃으면 연동 토큰을 다시 넣어야 함).

밖으로 나가는 호출과 위임

  • 폴링은 등록된 base_url로만 보낸다. 리다이렉트를 따르지 않고 시간 제한을 둔다. 사내 GitLab에 닿아야 하므로 사설 주소는 허용한다.
  • global.manage_cicd는 사내 주소로 나가는 호출을 만들 수 있으므로: 토큰 평문은 등록자에게도 다시 보여 주지 않고, 연동 만들기·바꾸기·비밀 다시 발급·지우기는 감사 로그(로거 openpms.audit, INFO: 누가·무엇을·연동 id와 이름. 토큰·비밀·URL의 사용자 정보는 남기지 않음)에 남기고, "연결 확인"은 상대 본문 없이 성공/실패와 HTTP 코드만 돌려준다.
  • HTTP·DB를 기다리는 동안 synchronized·computeIfAbsent 안에 있지 않는다(BUG-012).

5동작

  • 참조 찾기: 커밋 메시지, MR 제목·설명, 브랜치 이름(feature/123-login처럼 숫자-)에서 #123을 찾는다.
  • 사람 맞추기: 커밋·MR 작성자 메일이 openPMS 사용자 메일과 같으면 그 사용자로, 아니면 이름 글자만 보여 준다.
  • 보완 폴링 cicd-poll(5분): 저장소마다 cursor 뒤의 커밋과 갱신된 MR을 읽는다. 웹훅으로 이미 받은 것은 유일 키로 건너뛴다.
  • 활동 기록 없음: 연결이 생겨도 작업 활동(journal)에 남기지 않는다(커밋이 많으면 활동이 묻힘). 활동 기록은 4단계 자동 전환 때만.
  • 정리 cicd-cleanup(매일): 90일 지난 cicd_events를 지운다.
  • 어댑터 인터페이스: verify(request), parse(event) → 정규화 이벤트, poll(repository, cursor), listRepositories(query), check(). 2단계 어댑터가 같은 인터페이스를 쓴다.

2단계에서 바뀜(2.9): 떼기는 기록을 남기고(확인 창 문구도 바뀜), 아래에 뗀 저장소 묶음과 다시 붙이기, 빌드 기록 정리가 생김. 관리 › CI/CD 연동의 지우기 확인 창은 기록이 남은 저장소가 있으면 대신 끄기를 권함.
