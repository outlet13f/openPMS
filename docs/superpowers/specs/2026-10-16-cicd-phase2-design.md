# 설계: CI/CD 연동 2단계 — 빌드·배포 상태

- 날짜: 2026-10-16
- 상태: 설계 합의(구현 계획 전)
- 앞 단계: `2026-10-15-cicd-design.md`(로드맵과 1단계), 1단계 구현과 허용 프로젝트(V26·V27, V1010·V1011)
- 요구사항: REQ-CICD-011 ~ (영역 3.24 CI/CD 연동)
- 마이그레이션: 스키마 V28, 개발 데이터 V1012(시작할 때 비어 있는지 확인)

## 1 목적과 범위

작업 패키지의 "개발" 탭에서 이 일과 연결된 커밋·MR의 **빌드 결과**와 **어느 환경(개발 → 스테이징 → 운영)까지 배포됐는지**를 같은 비중으로 보여 준다.

### 합의한 것

| 항목 | 결정 |
|---|---|
| 핵심 질문 | 빌드가 통과했나 + 어느 환경까지 나갔나(같은 비중) |
| 빌드를 받는 곳 | GitLab CI, GitHub Actions, Jenkins |
| 배포를 받는 곳 | Jenkins, Argo CD, GitLab·GitHub 환경(Environments) |
| 배포 ↔ 커밋 | 이미지 태그 = 커밋 번호(SHA). 배포가 담은 커밋 하나에서 포함 커밋을 계산 |
| 포함 계산 | 이전 배포와 비교(접근안 A): 코드 저장 도구의 비교 API로 두 배포 사이의 커밋을 얻음 |
| 환경 단위 | 프로젝트별 + 기본값(개발 → 스테이징 → 운영), 도구가 보낸 이름은 별칭으로 맞춤, 개발 리더가 관리 |
| 저장소 떼기 | 기록을 지우지 않음(뗀 시각만 남김). 1단계 동작을 바꿈 |
| 빌드 기록 정리 | 자동으로 지우지 않음. 개발 리더가 원할 때 날짜를 골라 정리 |
| 작업 목록 열·필터 | 2단계에 넣지 않음(3단계 릴리스 화면에서) |

### 버린 안

- 탭을 열 때 그때그때 조상 관계를 확인(B): 저장은 단순하지만 목록·릴리스에 쓸 "배포에 든 커밋" 데이터가 없고, 화면을 열 때 호출이 몰린다.
- 커밋 시각만 비교(C): 호출은 없지만 브랜치·체리픽·되돌리기에서 틀린다.

### 범위 밖 (2단계)

- 릴리스 화면·릴리스 노트, 작업 목록의 배포 환경 열·필터(3단계)
- 빌드·배포 실패 때 작업 상태 자동 전환·알림(4단계)
- openPMS에서 빌드·배포 실행
- 빌드 로그·테스트 보고서 보기(링크만)
- Jenkins·Argo CD에서 직접 읽어 오기(폴링)

## 2 이벤트를 받는 곳

새 정규화 이벤트 두 가지를 1단계의 `commit`·`merge_request`에 더한다.

- `pipeline`(빌드): 저장소, 도구의 빌드 id, 커밋 번호, 브랜치, 상태(`running`·`success`·`failed`·`canceled`), 링크, 시작·끝 시각, 보낸 도구
- `deployment`(배포): 저장소, 도구의 배포 id, 배포된 커밋 번호, 도구가 보낸 환경 이름, 상태(`running`·`success`·`failed`), 링크, 배포 시각, 보낸 도구

| 도구 | 빌드 | 배포 | 받는 방법 |
|---|---|---|---|
| GitLab | 파이프라인 알림(Pipeline Hook) | 배포 알림(Deployment Hook) | 기존 GitLab 연동. 폴링으로 보완(파이프라인·배포 API) |
| GitHub | Actions 실행 알림(`workflow_run`) | 배포 상태 알림(`deployment_status`) | 기존 GitHub 연동. 폴링으로 보완 |
| Jenkins | 빌드 결과 | 배포 단계 | 새 연동 종류 `jenkins`. 파이프라인 단계가 **표준 알림**을 서명해 보냄. Jenkinsfile 예시 제공. 웹훅만 |
| Argo CD | – | 동기화 성공·실패 | 새 연동 종류 `argocd`. Argo CD Notifications 웹훅에 **표준 알림** 틀을 넣음. 알림 틀 제공. 웹훅만 |

### 표준 알림 (Jenkins·Argo CD 공통)

JSON 한 가지 형식: `type`(`pipeline`·`deployment`), `repository`(저장소 경로 `group/name`), `id`(도구 쪽 id), `sha`, `image`(선택), `ref`(선택), `environment`(배포일 때), `status`, `url`, `at`(ISO 시각). 서명은 `X-OpenPMS-Signature: sha256=<본문 HMAC-SHA256(웹훅 비밀)>`.

- 커밋 번호: `sha`가 있으면 쓰고, 없으면 `image`의 태그에서 연동별 규칙(기본: 16진수 7~40자리)으로 뽑는다. 둘 다 없거나 짧은 번호가 여러 커밋과 맞으면 "커밋 모름"으로 기록만 남긴다.
- Argo CD 앱이 어느 저장소·환경인지는 앱 주석(`openpms.repository`, `openpms.environment`)에 적고, 알림 틀이 그 값을 담는다.

## 3 데이터 (마이그레이션 V28, 개발 데이터 V1012)

| 표 | 담는 것 | 비고 |
|---|---|---|
| `cicd_environments` | 프로젝트별 환경: 이름, 순서, 운영 여부, 별칭 목록, 숨김 | 별칭은 대소문자 무시로 맞춤. 배포 기록이 있으면 지우지 않고 숨김 |
| `cicd_pipelines` | 빌드: 저장소, 도구 빌드 id, 커밋 번호, 브랜치, 상태, 링크, 시작·끝, 보낸 도구, 갱신 시각 | `(저장소, 빌드 id)` 유일. 더 새로운 알림일 때만 상태를 바꿈 |
| `cicd_deployments` | 배포: 저장소, 환경(못 맞추면 비움), 도구가 보낸 환경 이름, 커밋 번호, 상태, 링크, 배포 시각, 보낸 도구, 포함 판정(`비교`·`일부`·`첫 배포`·`확인 중`·`확인 실패`·`커밋 모름`) | `(저장소, 도구 배포 id)` 유일 |
| `cicd_deployment_commits` | 배포로 새로 들어간 커밋 | 3단계 릴리스 노트가 씀 |
| `cicd_environment_commits` | **지금** 각 환경에 들어가 있는 커밋(환경, 저장소, 커밋, 들여온 배포) | "어느 환경까지 갔나"를 이 표로 답함. 되돌리기 배포가 빼면 지움 |
| `cicd_environment_heads` | 저장소·환경마다 지금 배포된 커밋 번호와 배포 | 배포 처리의 잠금 단위 |

그 밖의 바뀌는 것:

- `cicd_connections.kind`에 `jenkins`·`argocd`를 더하고, `tool_url`(링크 검사용 도구 주소)과 `image_tag_pattern`(이미지 태그 규칙)을 더한다. Jenkins·Argo CD는 API 토큰이 없다.
- `cicd_repositories.detached_at`을 더한다(아래 "저장소 떼기").
- 모듈 `cicd`를 쓰는 프로젝트마다 기본 환경 세 개를 넣는다: 개발(`dev`, `development`) · 스테이징(`stg`, `staging`) · 운영(`prod`, `production`, 운영 여부 켬). 새로 모듈을 켜는 프로젝트도 같다.
- 비교 결과에만 있던 커밋은 `cicd_commits`에 새로 넣고, 메시지의 `#번호`로 작업 연결을 만든다(1단계 규칙: 저장소가 붙은 프로젝트 트리 안에서만).
- 권한은 새로 만들지 않는다: 보기 `cicd.view`, 환경 설정·빌드 기록 정리 `cicd.manage`.

### 저장소 떼기 (1단계 동작을 바꿈)

- 떼어도 행을 지우지 않고 `detached_at`만 남긴다. 커밋·MR·작업 연결·빌드·배포·환경 기록이 모두 남는다.
- 뗀 저장소는 새 웹훅·폴링을 받지 않는다(붙지 않은 저장소와 같음). 이미 받은 기록은 개발 탭에 그대로 보이고 "뗀 저장소"로 표시한다.
- 같은 저장소를 다시 붙이면 같은 행을 되살린다(이전 기록과 끊은 연결이 이어짐). 다른 프로젝트에 붙이면 행의 프로젝트만 바뀌고, 이미 만든 작업 연결은 원래 작업에 남는다.
- 연동 삭제: 기록이 남은 저장소(뗀 것 포함)가 있으면 409. 대신 "끄기".

### 정리

- 빌드·배포 기록은 자동으로 지우지 않는다. 개발 리더가 프로젝트 설정 › 저장소에서 "빌드 기록 정리"를 고르면, 고른 날짜보다 오래된 그 프로젝트 저장소들의 빌드 기록을 지운다(확인 창에 건수, 감사 로그). 배포 기록과 환경 상태는 정리 대상이 아니다.
- `cicd_events`(처리 대기열)는 지금처럼 90일 뒤 자동 정리.

## 4 처리

모든 처리는 예약 작업 `cicd-process`가 한다. 바깥 API는 트랜잭션 밖에서 부르고 결과만 트랜잭션으로 저장한다.

### 빌드

- `(저장소, 빌드 id)`로 만들거나 고친다. 더 새로운 알림일 때만 상태를 바꾼다.
- 커밋 줄: 그 커밋 번호로 돈 최신 빌드. MR 줄: MR 원본 브랜치에서 돈 최신 빌드.

### Jenkins·Argo CD 알림의 저장소 찾기

- 표준 알림의 저장소 경로를 **그 연동의 허용 프로젝트에 붙은(떼지 않은) 저장소**의 경로와 맞춘다. 다른 팀 연동이 남의 저장소에 기록을 넣지 못한다.
- 못 찾으면 버린다(1단계와 같음). 비교 API는 그 저장소가 붙은 GitLab·GitHub 연동의 토큰으로 부른다.

### 배포 → 환경 상태

- `cicd_environment_heads` 행을 잠근 채 처리해 같은 환경의 배포를 차례로 반영한다.
- **성공한 배포만** 상태를 바꾼다. 진행 중·실패는 기록만.
- 늦게 온 옛 배포(지금 상태보다 배포 시각이 이른 것)는 기록만.
- 이전 배포가 있으면 비교 API를 양방향으로 부른다.
  - `비교(이전 → 새)`의 커밋 = 들어간 커밋: 환경별 커밋 표에 더하고 이 배포의 포함 목록에 넣는다.
  - `비교(새 → 이전)`의 커밋 = 빠진 커밋: 환경별 커밋 표에서 지운다.
  - 되돌리기 배포와 갈라진(핫픽스) 배포도 맞게 처리된다.
- 한 방향 최대 1,000개. 넘으면 이 배포를 "일부"로 표시하고 경고 로그.

### 첫 배포 (이전 배포가 없음)

- 이 저장소에서 작업에 연결된 커밋 중 최근 것부터 최대 200개를 `비교(그 커밋 → 배포 커밋)`으로 확인해 "뒤에 있음"·"같음"이면 포함으로 본다.
- 배포 처리와 나눠 백그라운드로 하고(실행마다 저장소당 최대 50번 호출), 끝날 때까지 "확인 중". 200개보다 오래된 연결은 "첫 배포 이전"으로 남긴다. 다음 배포부터는 일반 비교.

### 환경 이름 맞추기

- 도구가 보낸 환경 이름을 그 프로젝트 환경의 별칭과 맞춘다(대소문자 무시). 못 맞추면 "환경 미지정"으로 기록만.
- 별칭을 더하면 그 이름의 미지정 배포를 시간 순서대로 다시 처리한다.

### 실패와 다시 시도

- 비교 API 실패(시간 초과·권한 없음 등)는 다음 실행에서 최대 5번 다시 시도하고, 그래도 안 되면 "확인 실패". 로그에는 연동 id·저장소 id·상태 코드만.

## 5 화면

### 작업 패키지 › 개발 탭 (`cicd.view`)

- 맨 위 환경 줄: `개발 ✓ 10-14 15:20 · 스테이징 ✓ 10-15 09:02 · 운영 –`. 연결된 커밋 중 하나라도 그 환경에 있으면 ✓와 배포 시각, 일부면 "일부(3개 중 2개)". "확인 중"·"일부만 확인됨"·"확인 실패"는 글자로. 환경 이름은 해당 배포 링크(새 창).
- MR·커밋 줄 옆 빌드 배지(성공·실패·진행 중·취소, 글자로도 표시, 누르면 빌드 화면 새 창).
- 커밋 줄에 들어간 환경을 작은 글자로("스테이징·개발"). 뗀 저장소는 "뗀 저장소" 표시.

### 프로젝트 설정 › 환경 (새 섹션, 보기 `cicd.view`, 고치기 `cicd.manage`)

- 환경 목록: 이름, 순서(위·아래 버튼), 운영 여부, 별칭(쉼표). 추가·삭제(배포 기록이 있으면 숨기기만).
- 환경 미지정 배포: 도구가 보낸 이름, 건수, 마지막 시각, "○○ 환경의 별칭으로 더하기".

### 프로젝트 설정 › 저장소

- 뗀 저장소 묶음과 다시 붙이기.
- "빌드 기록 정리"(`cicd.manage`): 날짜 고르기 → 지울 건수 확인.

### 관리 › CI/CD 연동

- 종류에 Jenkins·Argo CD 추가(API 토큰 칸 없음, 웹훅 비밀만, 도구 주소 칸).
- 연동 상세에 알림 설정 예시와 복사 버튼: Jenkins는 Jenkinsfile 조각(서명한 알림을 보내는 셸 단계), Argo CD는 Notifications 웹훅 서비스·알림 틀·앱 주석 예. 웹훅 주소는 채우고 비밀 자리는 `<웹훅 비밀>`.
- "이미지 태그 → 커밋 번호" 규칙 칸(기본값, 예시 태그로 바로 시험).

### 가짜 데이터 계층·도움말

- 가짜 데이터 계층도 같은 규칙·문구, 시드에 빌드·배포 몇 건과 기본 환경. `SCHEMA` 올림.
- 도움말: 07 §16.6 빌드·배포 보기, 16.7 환경 설정, 10 §9.18에 Jenkins·Argo CD 연동 새 절(기존 번호는 바꾸지 않음).

## 6 보안

- 받는 경로는 `/api/v1/hooks/cicd/{key}` 하나 그대로. Jenkins·Argo CD는 `X-OpenPMS-Signature` HMAC 검증, 거절은 모두 같은 404.
- Jenkins·Argo CD 알림은 그 연동의 허용 프로젝트에 붙은 저장소에만 기록한다.
- 빌드·배포 링크 검사: GitLab·GitHub는 저장소 주소와 같은 호스트, Jenkins·Argo CD는 연동의 도구 주소 호스트만. 아니면 링크를 비운다.
- 관리 › CI/CD 연동은 지금처럼 API 토큰으로 닫혀 있다. 환경 설정·빌드 기록 정리도 세션만.
- 감사 로그(`openpms.audit`): 빌드 기록 정리, 환경 추가·삭제·별칭 변경, 저장소 떼기·다시 붙이기.
- 바깥 호출은 1단계 규칙 그대로(10초 전체 마감, 2 MiB, 리다이렉트 안 따름). 가상 스레드 규칙(`synchronized` 금지, `computeIfAbsent` 안에서 DB·HTTP 대기 금지).

## 7 테스트

### JUnit

- 빌드: 같은 빌드 여러 번 → 최신 상태, 늦게 온 옛 알림 무시
- 배포: 이전과 비교해 더해짐, 되돌리기는 빠짐, 갈라진 배포 양쪽, 1,000개 넘으면 "일부"
- 첫 배포: 200개 상한, 나눠 처리, "확인 중" → 완료
- 환경: 별칭 대소문자 무시, 미지정 배포가 별칭 추가 뒤 다시 처리, 늦게 온 성공 배포가 상태를 되돌리지 않음
- Jenkins·Argo CD: 서명 검증, 허용 프로젝트 밖 저장소 무시, 이미지 태그에서 커밋 번호, 커밋 모름
- 저장소 떼기: 기록 유지, 새 알림 무시, 다시 붙이면 이어짐(끊은 연결 포함), 기록이 있으면 연동 삭제 409
- 빌드 기록 정리: 날짜 기준, 배포는 남음, 권한
- 동시성: 같은 환경에 두 배포가 동시에 와도 차례로
- 성능 예산: 개발 탭(환경 줄·빌드 배지 포함) SQL 수·응답 시간

### e2e

- F23: 가짜 Git 서버에 비교 API를 더하고, GitLab 파이프라인·배포 알림 → 개발 탭에 빌드 배지와 "개발 ✓", Jenkins 표준 알림으로 운영 배포 → "운영 ✓", 되돌리기 배포 → "운영 –". 저장소를 떼고도 기록이 보임.
- 프로젝트 설정 › 환경에 접근성 검사.

## 9 위험과 대응

| 위험 | 대응 |
|---|---|
| 비교 API 호출이 많아 도구에 부담 | 배포마다 두 번, 첫 배포는 실행마다 저장소당 50번 상한 |
| 이미지 태그가 커밋 번호가 아닌 팀 | 연동별 태그 규칙, 못 뽑으면 "커밋 모름"으로 기록만 |
| 다른 팀이 가짜 배포를 넣음 | 연동별 웹훅 비밀 + 허용 프로젝트에 붙은 저장소만 |
| 배포가 순서 없이 도착 | 환경 머리 행 잠금, 배포 시각으로 옛 배포 무시 |
| 저장소 떼기가 기록을 지우지 않아 DB가 커짐 | 빌드 기록은 사용자가 정리, 배포 기록은 작아서 유지 |
| GitHub 비교 API의 커밋 수 한도 | 한 방향 1,000개 상한과 "일부" 표시 |
