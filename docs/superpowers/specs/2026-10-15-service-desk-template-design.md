# 설계: 서비스 데스크 템플릿

- 날짜: 2026-10-15
- 상태: 설계 합의(사용자 승인 2026-10-15)
- 선행: ITSM 1단계(`2026-10-14-itsm-design.md`, 서비스 데스크·SLA·포털), 2단계(`2026-10-14-itsm-phase2-catalog-design.md`, 카탈로그·승인)
- 관련 요구사항: REQ-ITSM-023~(이 작업에서 번호를 정한다)

## 1. 목적

지금 쓰고 있는 "IT 서비스 데스크"의 설정을 템플릿으로 만들어 두고, 새 서비스 데스크(인사, 총무 등)는 그 템플릿에서 만들면 SLA·우선순위 행렬·카탈로그가 함께 따라오게 한다. 서비스 데스크 모듈(`service_desk`)은 그대로 "이 프로젝트는 서비스 데스크"라는 스위치로 둔다.

### 합의한 것

| 항목 | 결정 |
| --- | --- |
| 모듈 | 유지한다. 비공개 강제·포털 노출·`service.*` 권한·SLA·메일 작업이 모듈에 묶여 있다 |
| 복사 범위 | 설정만. 서비스 데스크의 티켓은 복사하지 않는다 |
| 템플릿 프로젝트 | 지금의 IT 서비스 데스크는 템플릿으로 표시하지 않는다(포털이 템플릿 프로젝트를 빼고 보여 주므로 요청자가 요청할 수 없게 됨). 별도 프로젝트 "서비스 데스크 템플릿"을 둔다 |

### 범위 밖

- 템플릿을 바꾼 뒤 이미 만든 데스크에 다시 반영하는 동기화
- 복사할 때 처리 그룹·승인자를 바꿔 끼우는 대화상자
- 티켓(예시 티켓 포함) 복사

## 2. 복사 규칙 (`ProjectCopy`)

원본 프로젝트에 모듈 `service_desk`가 켜져 있으면, 새 프로젝트를 만들 때(템플릿에서 만들기 `POST /projects` + `templateId`, 프로젝트 복사 `POST /projects/{id}/copy` 모두) 다음을 **항상** 복사한다. 복사할 항목(`copy`) 선택과 상관없다.

- `sla_policies`: 유형·우선순위·서비스 달력·첫 응답·해결 시간. 서비스 달력은 전체 공통이라 같은 id를 가리킨다. 새 id.
- `priority_matrix`: 영향 × 긴급도 → 우선순위.
- 카탈로그
  - `catalog_categories`: 이름·순서. 새 id.
  - `catalog_items`: 이름·설명·유형·기본 우선순위·받는 처리 그룹·포털에 보임·순서, 분류는 복사한 분류의 새 id로. 새 id.
  - `catalog_item_fields`: 사용자 정의 필드·순서·필수(필드는 전체 공통이라 같은 id).
  - `catalog_item_approval_steps`: 단계 번호·종류.
- 처리 그룹(`user_groups`)·사용자 정의 필드·서비스 달력은 전체 공통이라 복사하지 않고 같은 것을 참조한다.

원본이 서비스 데스크이면 `copy`에 `workPackages`가 있을 때 422 `copy` "서비스 데스크의 티켓은 복사하지 않습니다."로 막는다. 멤버·버전·범주·보드·저장된 목록은 지금처럼 고른 대로 복사한다. 보드·저장된 목록이 티켓을 가리키지 않으므로 그대로 둔다.

비공개 강제(공개 + `service_desk`면 422 "서비스 데스크를 쓰는 프로젝트는 공개할 수 없습니다.")는 이미 있는 규칙을 그대로 쓴다.

복사는 표마다 `insert … select` 한 번씩으로 하고(항목 수에 비례하는 SQL 없음), 프로젝트를 만드는 트랜잭션 안에서 한다. 저널·웹훅은 프로젝트 생성의 기존 동작 그대로다.

## 3. 템플릿 프로젝트

- 개발 데이터 V1006 `dev_service_desk_template.sql`: 비공개 템플릿 프로젝트 "서비스 데스크 템플릿"(식별자 `service-desk-template`, `is_template = true`). IT 서비스 데스크(`service-desk`)의 모듈·유형·사용자 정의 필드 연결·SLA 정책·우선순위 행렬·카탈로그(분류·항목·양식 필드·승인 단계)를 담고, 티켓·멤버 외 데이터는 없다. 고정 id는 `backend/scripts/ids.py`(uuid5)로 만든다.
- 실제 설치에서는 운영자가 화면에서 같은 일을 한다: IT 서비스 데스크 › 복사(설정만) → 새 프로젝트의 설정에서 **템플릿으로 쓰기**. 운영자 매뉴얼에 새 절로 적는다.
- 번호: ITSM 3단계 설계서가 쓰려던 V1006은 한 칸씩 민다(3~6단계는 V1007부터). 동료 세션의 CI/CD 계획이 V1010을 잡아 두었으므로 그 세션에 알린다.

## 4. 화면

- 새 프로젝트(`/projects/new`)와 프로젝트 복사 대화상자에서 원본(템플릿)이 서비스 데스크이면 복사 선택지의 **작업**을 숨기고 안내 "서비스 데스크는 SLA·우선순위 행렬·카탈로그를 함께 복사하고 티켓은 복사하지 않습니다."를 보인다.
- 공개 체크는 이미 막혀 있는지 확인하고, 없으면 원본이 서비스 데스크일 때 끈다.

## 5. 테스트

- JUnit `ServiceDeskTemplateIT`
  - 템플릿에서 만든 새 데스크에 SLA 정책·행렬·카탈로그(분류·항목·양식 필드·승인 단계)가 같은 값, 새 id로 생김
  - 새 데스크의 카탈로그·SLA를 고쳐도 원본은 그대로(독립)
  - 원본이 서비스 데스크이고 `copy`에 `workPackages`면 422, 공개면 422
  - 서비스 데스크가 아닌 원본의 복사는 바뀌지 않음
  - 새 데스크가 포털 `GET /portal/desks`에 카탈로그와 함께 나오고, 항목 요청에 SLA 정책이 붙음
  - 복사의 SQL 수가 카탈로그 항목 수에 비례하지 않음
- e2e F22: 김서연이 "서비스 데스크 템플릿"에서 "인사 서비스 데스크"를 만든다 → 최민지 포털에 새 데스크와 카탈로그가 보이고 요청하면 SLA 기한이 붙는다. 접근성 검사(새 프로젝트 화면의 안내).
- 가짜 데이터 계층: 같은 복사 규칙과 템플릿 시드, `SCHEMA` 올림.
