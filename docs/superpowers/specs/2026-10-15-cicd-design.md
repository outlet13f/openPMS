# 설계: CI/CD 연동 — 로드맵과 1단계 연동 기반·추적성

- 날짜: 2026-10-15
- 상태: 설계 합의(구현 계획 전)
- 요구사항: REQ-CICD-001 ~ (1단계). 새 영역 3.25 CI/CD 연동
- 범위 밖이던 REQ-OOS-011(GitHub·GitLab 연동과 리포지토리)을 일부 들여옴

## 1 목적

작업 패키지와 개발 도구(코드 저장소·CI·배포)를 이어서, "이 일이 어느 MR/PR과 커밋으로 처리됐고, 빌드가 통과했고, 어느 환경까지 배포됐는지"를 openPMS 안에서 본다. 이어서 릴리스 관리, 이벤트에 따른 자동화, ITSM 변경 관리와의 연결까지 단계로 넓힌다.

### 합의한 것

| 항목 | 결정 |
|---|---|
| 뜻 | 제품 기능(openPMS의 새 영역). 이 저장소 자체의 CI 파이프라인은 다루지 않음 |
| 연동 도구 | GitLab(자체 설치), GitHub(Enterprise·Cloud), Jenkins, Argo CD 등 배포 도구 |
| 목표 | 추적성, 릴리스·배포 관리, 자동화, ITSM 변경 관리 연결을 모두 담음(단계로 나눔) |
| 받는 방식 | 웹훅으로 바로 반영 + 주기 폴링으로 놓친 이벤트 보완. 밖에서 들어올 수 없는 도구는 폴링만 |
| 자동화 | 프로젝트별 규칙, 기본 꺼짐. 워크플로를 지키고 연동 이름으로 기록 |
| 구조 | 공통 이벤트 수집 계층 + 도구별 어댑터(접근안 A) |
| 권한 | 일반 사용자(멤버)는 보기·연결 고치기, 개발 리더는 저장소·규칙 관리, 도구 연동 등록은 전역 권한으로 위임 가능 |
| 자격 증명 | `OPENPMS_SECRET_KEY`로 AES-GCM 암호화해 저장 |

### 고른 접근: 공통 이벤트 수집 계층 + 어댑터

웹훅과 폴링 결과를 모두 정규화한 이벤트(`commit`·`merge_request`·`pipeline`·`deployment`)로 바꿔 `cicd_events`에 쌓고, 그 위에 연결·릴리스·자동화·변경 관리를 올린다. 새 도구는 어댑터 하나(서명 검증·파싱·폴링)만 더한다. 같은 이벤트가 웹훅과 폴링으로 두 번 와도 `(연동, delivery_key)` 유일 키로 한 번만 반영한다.

버린 안: 도구별 독립 모듈(도구 4개 × 목표 4개로 규칙·화면이 중복), 외부 스크립트에만 맡김(서명 검증·복구가 각 팀 몫). 다만 정형 웹훅이 약한 도구(Jenkins 등)를 위해 2단계에 범용 API 어댑터를 둔다.

### 이름

ITSM 4단계(CMDB)의 CI는 구성 항목(configuration item, `work_package_cis`)이다. 겹치지 않게 이 영역의 식별자는 `cicd_`·`pipeline`·`deployment`를 쓰고, 화면 문구도 "CI/CD"나 "빌드·배포"로 쓴다.

### 범위 밖 (1단계)

- 파이프라인·배포 상태, Jenkins·Argo CD(2단계)
- 릴리스 화면(3단계), 상태 자동 전환(4단계), 변경 관리 연결(5단계)
- openPMS에서 MR/PR을 만들거나 병합하는 쓰기 동작(전 단계 범위 밖)
- 저장소 파일 보기·코드 검색(원본의 리포지토리 브라우저에 해당, 범위 밖 유지)

## 2 로드맵

| 단계 | 범위 | 기반 | 마이그레이션 |
|---|---|---|---|
| 1 연동 기반 + 추적성 | 도구 연동 등록, 들어오는 웹훅, 보완 폴링, 이벤트 정규화, `#123` 참조로 작업 연결, 작업 "개발" 탭. GitLab·GitHub 어댑터 | 새 모듈 `cicd` | V26, V1010 |
| 2 빌드·배포 상태 | 파이프라인·배포 이벤트, Jenkins·Argo CD·범용 API 어댑터, 환경(개발·스테이징·운영) 정의, 작업별 "어느 환경까지 갔나" | 1 | V27, V1011 |
| 3 릴리스 관리 | 기존 `versions`를 릴리스로 넓힘: 포함 작업·MR·배포 이력, 환경별 현황 화면, 릴리스 노트 내보내기 | 1·2 | V28, V1012 |
| 4 자동화 규칙 | 프로젝트별 규칙(기본 꺼짐): 이벤트 → 상태 전환(워크플로 준수)·알림, `closes #123` 같은 명령. 연동 이름으로 `journals.cause`에 기록 | 1·2 | V29, V1013 |
| 5 변경 관리 연결 | 운영 배포 ↔ ITSM 변경 요청, 승인 없는 운영 배포 감지·경고, 실행 계획서 2~4절에 빌드·배포 증거 자동 첨부 | 2·3 + ITSM 5단계(V24) | V30, V1014 |

ITSM 2~6단계가 V21–V25·V1005–V1009를 잡아 두었으므로 V26·V1010부터 쓴다. 시작할 때 번호가 비어 있는지 확인한다. 1~4단계는 ITSM과 따로 진행할 수 있고, 5단계만 ITSM 5단계 뒤에 한다.

### 단계 사이에 오가는 것

| 단계 | 받는 것 | 넘겨주는 것 |
|---|---|---|
| 1 | 작업 패키지, 프로젝트, 역할, 예약 작업 | 연동·저장소, `cicd_events`, 커밋·MR 표, 작업 연결, 어댑터 인터페이스 |
| 2 | 어댑터 인터페이스, 이벤트 수집 | 파이프라인·배포 표, 환경 정의 |
| 3 | `versions`, MR·배포 | 릴리스 범위·이력 |
| 4 | 정규화 이벤트, 워크플로 | 규칙 엔진, 자동 전환 기록 |
| 5 | 배포·릴리스, ITSM 변경 요청·실행 계획서 | 변경 ↔ 배포 연결, 무승인 배포 경고·웹훅 이벤트 |

## 3 데이터 (마이그레이션 V26 `cicd.sql`, 개발 데이터 V1010)

| 표 | 핵심 열 | 비고 |
|---|---|---|
| `cicd_connections` | kind(`gitlab`·`github`), name, base_url, `api_token_enc`, `webhook_secret_enc`, `hook_key`(경로용 난수), active, created_by, created_at, updated_at | 연동 등록 권한자만 다룸 |
| `cicd_repositories` | connection_id, external_id, full_path, web_url, project_id, poll_cursor, last_polled_at | 저장소 하나는 프로젝트 하나에 붙음. `(connection_id, external_id)` 유일 |
| `cicd_events` | connection_id, repository_id, kind, delivery_key, payload(jsonb, 필요한 필드만), via(`webhook`·`poll`), status(`pending`·`done`·`failed`), error, received_at, processed_at | `(connection_id, delivery_key)` 유일. 90일 지나면 지움 |
| `cicd_commits` | repository_id, sha, title, author_name, author_email, user_id, committed_at, web_url | `(repository_id, sha)` 유일 |
| `cicd_merge_requests` | repository_id, iid, title, state(`open`·`draft`·`merged`·`closed`), source_branch, target_branch, author_name, user_id, merged_at, updated_at, web_url | `(repository_id, iid)` 유일 |
| `work_package_cicd_links` | work_package_id, commit_id 또는 merge_request_id(둘 중 하나), source(`message`·`branch`·`title`·`manual`), created_by, dismissed_by, dismissed_at | 끊은 연결은 행을 남기고 표시만 함(다시 생기지 않게) |

- 모듈 `cicd`를 넣고 `projects_known_modules` check 제약을 넓힌다.
- 개발 데이터 V1010: 연동 1개(가짜 GitLab), 저장소 2개, 커밋·MR 몇 개와 연결. SQL로는 AES-GCM 값을 만들 수 없으므로 연동은 `api_token_enc`·`webhook_secret_enc`가 비고 `active = false`다(화면에서 "비밀 다시 발급"과 토큰 입력으로 켠다).
- 토큰이 없는 연동(`api_token_enc`가 빔)은 폴링과 저장소 검색을 하지 않고 웹훅만 받는다. 저장소 검색(붙이기 화면)은 토큰이 있어야 한다.
- jOOQ 생성 코드를 다시 만들어 커밋한다.

## 4 권한과 보안

### 권한

| 권한 | 할 수 있는 일 | 기본 역할 |
|---|---|---|
| `cicd.view` | 개발 탭 보기(MR/PR·커밋) | 멤버·참관자·개발 리더·프로젝트 관리자 |
| `cicd.link` | MR/PR 주소를 붙여 손으로 연결, 잘못 붙은 연결 끊기 | 멤버·개발 리더·프로젝트 관리자 |
| `cicd.manage` | 프로젝트에 저장소 붙이기·떼기(뒤 단계: 환경·릴리스·자동화 규칙) | 개발 리더·프로젝트 관리자 |
| `global.manage_cicd`(전역) | 관리 › CI/CD 연동에서 도구 연동 등록·수정 | 새 전역 역할 "CI/CD 연동 관리자"(시스템 관리자가 아니어도 줄 수 있음) |

- 새 프로젝트 역할 "개발 리더"를 V26이 운영 데이터로 넣는다(V20의 요청자 역할과 같은 방식). 내장 역할이 아니어서 관리 › 역할에서 고칠 수 있다. 권한은 멤버 + `cicd.manage`.
- 이미 설치된 곳: 작업 보기 권한이 있는 프로젝트 역할에 `cicd.view`, 작업 편집 권한이 있는 역할에 `cicd.link`를 더한다.
- 비멤버(공개 프로젝트)에는 주지 않는다(커밋 제목은 사내 정보). 요청자에게는 어떤 `cicd.*`도 주지 않고, 포털에 개발 정보를 내보내지 않는다.
- `cicd.*`는 `Ctx.MODULE_OF`로 모듈 `cicd`에 묶는다. 모듈이 꺼진 프로젝트에서는 탭이 숨고 API는 404.
- `GLOBAL_PERMISSIONS`에 `global.manage_cicd`를 더한다.

### 사람별 권한 (기본값)

권한은 역할에 묶인다. 프로젝트 역할은 프로젝트마다 멤버에게 주고(같은 사람이 프로젝트마다 다를 수 있음), 전역 역할은 관리자가 사용자에게 준다. 역할의 권한은 관리 › 역할에서 고칠 수 있다.

| 사람(역할) | 보기 | 연결 고치기 | 저장소 붙이기 | 도구 등록 |
|---|:-:|:-:|:-:|:-:|
| 요청자(서비스 데스크 포털) | – | – | – | – |
| 비멤버(공개 프로젝트 방문자) | – | – | – | – |
| 참관자 | ✓ | – | – | – |
| 멤버(일반 사용자) | ✓ | ✓ | – | – |
| 개발 리더(새 역할) | ✓ | ✓ | ✓ | – |
| 프로젝트 관리자 | ✓ | ✓ | ✓ | – |
| CI/CD 연동 관리자(전역 역할) | –¹ | –¹ | –¹ | ✓ |
| 시스템 관리자 | ✓ | ✓ | ✓ | ✓ |

¹ 전역 역할은 도구 등록만 준다. 프로젝트의 개발 정보를 보려면 그 프로젝트에서도 역할이 있어야 한다. 보통 개발 리더에게 함께 준다.

### 쓰는 흐름

1. CI/CD 연동 관리자가 관리 › CI/CD 연동에 사내 GitLab을 등록하고, 한 번 보이는 웹훅 주소·비밀을 GitLab에 넣는다.
2. 개발 리더가 프로젝트 설정 › 저장소에서 저장소를 붙인다.
3. 멤버는 커밋 메시지나 브랜치 이름에 `#123`을 적는다. 작업 #123의 개발 탭에 MR·커밋이 나타나고, 엉뚱하게 붙은 것은 멤버가 끊는다.
4. 참관자(기획·QA 등)는 개발 탭에서 상태만 본다.

이미 설치된 곳은 역할 이름이 아니라 가진 권한으로 판단해 새 권한을 더하고(`scope = 'project'`이고 `builtin`이 없는 역할 중 `wp.view`가 있으면 `cicd.view`, `wp.edit`이 있으면 `cicd.link`, `project.manage_members`가 있으면 `cicd.manage`. 비멤버·요청자 내장 역할은 건드리지 않음), "개발 리더"는 새로 생기므로 프로젝트 관리자가 해당자의 역할을 바꾼다.

### 들어오는 웹훅

- 경로 `POST /api/v1/hooks/cicd/{hookKey}`. `SpaConfig`가 `/api` 밖의 주소를 `index.html`로 돌려주고 운영 프록시도 `/api`만 백엔드로 보내므로 `/api` 아래에 둔다. `SecurityConfig`에서 이 경로만 `permitAll`과 CSRF 제외를 건다(`/api/**` authenticated보다 앞에).
- GitHub는 `X-Hub-Signature-256`(HMAC-SHA256), GitLab은 `X-Gitlab-Token`을 상수 시간 비교로 검증한다.
- 없는 키와 서명 실패는 같은 404로 답한다(연동이 있는지 드러나지 않게).
- 본문은 1 MiB까지(넘으면 413). 요청 안에서는 이벤트를 저장만 하고 202로 바로 답한다. 처리는 예약 작업 `cicd-process`(15초)가 한다.
- 다시 보낸 같은 이벤트는 delivery id(`X-GitHub-Delivery`, `X-Gitlab-Event-UUID`)로 한 번만 반영한다.

### 프로젝트 경계

`#123`은 그 저장소가 붙은 프로젝트(와 하위 프로젝트)의 작업일 때만 연결한다. 다른 프로젝트의 작업 번호를 커밋에 적어도 연결되지 않고, 그 작업이 있는지도 드러나지 않는다. 손으로 연결할 때도 같은 검사를 한다.

### 자격 증명

- 도구 API 토큰과 웹훅 비밀은 환경 변수 `OPENPMS_SECRET_KEY`(32바이트를 Base64로 적은 값, `openssl rand -base64 32`, 설정 키 `openpms.secret-key`)로 AES-GCM 암호화해 저장한다. dev 프로필은 고정된 개발용 키를 기본값으로 두고, 운영 기본값은 빈 값이라 연동 저장이 422 "암호화 키(OPENPMS_SECRET_KEY)가 설정되지 않았습니다."로 막힌다.
- API는 끝 4자리만 돌려준다. 웹훅 비밀은 만들 때 한 번만 보여 주고, 이후에는 다시 발급만 한다.
- 토큰은 읽기 전용 범위(GitLab `read_api`, GitHub contents·pull requests read)를 쓰도록 화면에서 안내한다.
- 키 보관·백업은 운영자 매뉴얼에 적는다(키를 잃으면 연동 토큰을 다시 넣어야 함).

### 밖으로 나가는 호출과 위임

- 폴링은 등록된 base_url로만 보낸다. 리다이렉트를 따르지 않고 시간 제한을 둔다. 사내 GitLab에 닿아야 하므로 사설 주소는 허용한다.
- `global.manage_cicd`는 사내 주소로 나가는 호출을 만들 수 있으므로: 토큰 평문은 등록자에게도 다시 보여 주지 않고, 연동 만들기·바꾸기·비밀 다시 발급·지우기는 감사 로그(로거 `openpms.audit`, INFO: 누가·무엇을·연동 id와 이름. 토큰·비밀·URL의 사용자 정보는 남기지 않음)에 남기고, "연결 확인"은 상대 본문을 돌려주지 않고 성공/실패와 HTTP 코드만 돌려준다.
- HTTP·DB를 기다리는 동안 `synchronized`·`computeIfAbsent` 안에 있지 않는다(BUG-012).

## 5 동작

- 참조 찾기: 커밋 메시지, MR 제목·설명, 브랜치 이름(`feature/123-login`처럼 `숫자-`)에서 `#123`을 찾는다.
- 사람 맞추기: 커밋·MR 작성자 메일이 openPMS 사용자 메일과 같으면 그 사용자로 보여 주고, 아니면 이름 글자만 보여 준다.
- 보완 폴링 `cicd-poll`(5분): 저장소마다 cursor 뒤의 커밋과 갱신된 MR을 읽는다. 웹훅으로 이미 받은 것은 유일 키로 건너뛴다.
- 연결이 생겨도 작업 활동(journal)에는 남기지 않는다(커밋이 많으면 활동이 묻힘). 활동 기록은 4단계 자동 전환 때만 남긴다.
- 정리 작업 `cicd-cleanup`(매일): 90일 지난 `cicd_events`를 지운다.
- 어댑터 인터페이스: `verify(request)`, `parse(event) → 정규화 이벤트`, `poll(repository, cursor)`, `listRepositories(query)`, `check()`. 2단계 어댑터가 같은 인터페이스를 쓴다.

## 9 위험과 대응

| 위험 | 대응 |
|---|---|
| 인증 없이 열리는 첫 경로 | 경로 하나만 열고, 서명 검증·같은 404·크기 제한·저장 후 비동기 처리. 보안 IT로 고정 |
| 커밋에 적은 번호로 남의 프로젝트 작업에 연결 | 저장소가 붙은 프로젝트 범위로만 연결, 테스트로 고정 |
| 위임 받은 사람이 사내 주소로 호출을 만듦 | 토큰 비노출, 감사 로그, 연결 확인 응답에 상대 본문 없음 |
| 암호화 키 분실 | 운영자 매뉴얼에 보관·백업, 키가 없으면 저장을 막고 토큰 재입력 안내 |
| 웹훅 폭주로 서버가 느려짐 | 요청에서는 저장만, 처리는 예약 작업이 묶어서. `PerfBudgetIT` |
| CMDB의 CI와 이름 혼동 | 식별자 `cicd_`, 화면 문구 "CI/CD" |
