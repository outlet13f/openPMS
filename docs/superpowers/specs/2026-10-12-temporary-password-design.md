# 설계: 관리자가 임시 비밀번호로 사용자 등록·재발급

- 날짜: 2026-10-12
- 상태: 설계 합의(구현 계획 전)
- 관련 요구사항: 새 REQ-AUTH-005 (기존 REQ-AUTH-001 로그인, REQ-AUTH-003 초대와 함께)

## 1. 목적

사내 SMTP가 없거나 메일이 닿지 않는 환경에서도 관리자가 사용자를 바로 등록하고 쓰게 한다. 지금은 사용자를 만드는 길이 초대 메일(REQ-AUTH-003)과 SSO 첫 로그인뿐이고, 비밀번호를 잊으면 재설정 메일로만 되찾는다.

### 합의한 것

| 항목 | 결정 |
| --- | --- |
| 등록 방식 | 관리자가 메일 없이 바로 만든다. 기존 초대 메일은 그대로 두고 만들 때 둘 중 고른다 |
| 초기 비밀번호 | 앱이 임시 비밀번호를 만든다. 관리자가 직접 입력하지 않는다 |
| 첫 로그인 | 임시 비밀번호로 로그인하면 반드시 새 비밀번호를 정해야 쓸 수 있다 |
| 기존 계정 | 비밀번호를 잊은 사람, 초대를 수락하지 못한 사람에게도 임시 비밀번호를 다시 발급한다 |
| 관리자가 보기 | 사용자가 새 비밀번호를 정하거나 기한이 지날 때까지 관리자가 언제든 다시 보고 전달한다 |
| 강제 방식 | 임시 비밀번호로는 세션을 만들지 않고 일회용 변경 토큰을 준다(아래 4절). 화면만 막는 방식과 제한된 세션 방식은 쓰지 않는다 |

### 범위 밖

- 로그인 화면의 자가 가입
- CSV 등으로 여러 명 한꺼번에 등록
- 관리자가 남의 비밀번호를 원하는 값으로 직접 정하기
- 임시 비밀번호를 메일·문자로 자동 발송(전달은 관리자가 한다)
- 관리 활동 감사 기록 화면(서버 로그 한 줄만 남긴다)

## 2. 데이터 (마이그레이션 V19)

### 2.1 새 테이블 `temporary_passwords`

| 칸 | 형식 | 설명 |
| --- | --- | --- |
| `user_id` | uuid PK, FK `users(id)` on delete cascade | 사용자마다 한 행 |
| `password` | text not null | 임시 비밀번호 평문. 조회 API(3.3) 말고는 어디로도 내보내지 않는다 |
| `expires_at` | timestamptz not null | 발급 시각 + `auth.invitation_ttl_hours`(기본 168시간) |
| `issued_by` | uuid FK `users(id)` on delete set null | 발급한 관리자 |
| `issued_at` | timestamptz not null default now() | |

- 다시 발급하면 그 행을 덮어쓴다(upsert).
- 비밀번호가 정해지는 모든 경로에서 그 사람의 행을 지운다: 첫 로그인 변경(4.2), 재설정 링크(`/auth/password-reset/confirm`), 초대 수락(`/auth/invitations/{token}/accept`), 본인 변경(`PUT /account/password`).
- 로그인 확인은 지금처럼 `users.password_hash`(해시)로만 한다. 행이 있으면 "지금 비밀번호는 임시"라는 뜻이다.
- 기한이 지난 행은 정리 작업 `token-cleanup`(`Housekeeping.tokens`, 매일 03:30, `OPENPMS_JOBS_ENABLED=true`인 인스턴스)이 지운다. 만료된 임시 비밀번호로 로그인을 시도할 때도 그 행을 바로 지운다.
- 행이 지워져도 `password_hash`는 남는다. 만료 뒤 그 비밀번호로 로그인하지 못하게 하는 것은 4.1의 판단이 맡는다: 만료로 지워진 사람은 `password_hash`를 비운다(아래 2.3).

### 2.2 `user_tokens.purpose` 넓히기

check 제약 `purpose in ('invitation', 'password_reset')`에 `'password_change'`를 더한다(4절의 변경 토큰).

### 2.3 만료 처리의 정확한 규칙

- 로그인할 때 행이 있고 `expires_at`이 지났으면: 행을 지우고, `users.password_hash`를 null로 만들고, 401 "임시 비밀번호가 만료되었습니다. 관리자에게 다시 발급을 요청하세요."
- 정리 작업도 같은 일을 한다(행 삭제 + `password_hash` null). 이렇게 해야 행이 지워진 뒤 옛 임시 비밀번호가 보통 비밀번호처럼 통하지 않는다.
- `password_hash`가 null인 활성 계정은 지금도 있는 상태(SSO 전용 계정)와 같다. 비밀번호 로그인은 실패하고, 재설정 메일이나 다시 발급으로 되찾는다.

## 3. 서버 API

모두 `/api/v1` 아래. 권한 판단은 기존 `AdminController.userManager()`(관리자 또는 전역 권한 `global.manage_users`)를 따른다.

### 3.1 `POST /admin/users` (기존, 확장)

- 본문에 `method`: `"invite"`(기본, 지금과 같음) 또는 `"temporaryPassword"`.
- `temporaryPassword`이면: 계정을 `active`로 만들고, 임시 비밀번호를 만들어 해시를 `password_hash`에, 평문을 `temporary_passwords`에 넣고, 메일은 보내지 않는다.
- 응답 201:
  - `invite`: 지금처럼 `AdminUser`.
  - `temporaryPassword`: `{ "user": AdminUser, "temporaryPassword": "…", "expiresAt": "…" }`.
- 관리자 지정(`isAdmin`) 규칙은 지금과 같다(관리자만).

### 3.2 `POST /admin/users/{id}/temporary-password` (새)

기존 계정에 다시 발급한다. 응답 200 `{ "temporaryPassword", "expiresAt" }`.

- 대상이 `invited`이면 `active`로 바꾸고 초대 토큰을 모두 무효로 한다.
- 실패 잠금을 푼다(`failed_login_count` 0, `locked_until` null).
- 그 사람의 `password_reset`·`password_change` 토큰을 무효로 한다.
- 그 사람의 모든 세션을 끝낸다(`Sessions.endAll`).
- 거절:

| 경우 | 응답 |
| --- | --- |
| 사용자 관리 권한 없음 | 403 "사용자를 관리할 권한이 없습니다." |
| 대상이 관리자인데 요청한 사람이 관리자가 아님 | 403 "관리자 계정은 관리자만 다룰 수 있습니다." |
| 대상이 나 자신 | 422 "내 비밀번호는 계정 설정에서 바꾸세요." |
| 대상이 잠김(`locked`) | 422 "잠긴 계정입니다. 먼저 잠금을 푸세요." |
| 대상이 삭제됨·없음 | 404 |

### 3.3 `GET /admin/users/{id}/temporary-password` (새)

- 응답 200 `{ "temporaryPassword", "expiresAt", "issuedBy": {id, name} | null, "issuedAt" }`.
- 권한과 거절은 3.2와 같다(잠김·나 자신 포함).
- 행이 없거나 만료되었으면 404 "유효한 임시 비밀번호가 없습니다."

### 3.4 `GET /admin/users` (기존, 확장)

- 각 사용자에 `temporaryPasswordUntil`(유효한 행의 `expires_at`, 없으면 null)을 더한다. 평문은 넣지 않는다.

### 3.5 공통 보안 규칙

- 3.1(`temporaryPassword`)·3.2·3.3 응답에는 `Cache-Control: no-store`를 붙인다.
- `IdempotencyFilter`는 `POST /admin/users`(초대 포함 경로 전체)와 `POST /admin/users/{id}/temporary-password`를 제외한다(`shouldNotFilter`). 저장하면 평문이 `idempotency_keys`에 24시간 남는다. 화면은 지금도 사용자 만들기에 키를 붙이지 않으므로 잃는 것은 없다.
- 발급(3.1·3.2)과 조회(3.3)는 서버 로그에 INFO 한 줄: 누가, 누구의 임시 비밀번호를, 발급/조회. 비밀번호는 남기지 않는다.
- 웹훅·활동 기록·메일에는 임시 비밀번호가 나가지 않는다.

### 3.6 임시 비밀번호 만들기

- `SecureRandom`, 길이 = max(16, 정책 최소 길이).
- 문자 집합에서 헷갈리는 글자(`0 O 1 l I`)를 뺀다. 특수 문자는 메신저로 옮겨도 깨지지 않는 것만 쓴다(`!@#$%*-_+=?`).
- 영문 소문자·대문자·숫자·특수 문자를 하나씩 반드시 넣고 섞는다. 만든 뒤 `PasswordPolicy.check`로 한 번 더 확인한다.

## 4. 로그인과 첫 비밀번호 변경

### 4.1 `POST /auth/login` (기존, 확장)

비밀번호가 맞은 뒤:

1. 그 사람의 `temporary_passwords` 행이 없으면 지금과 같다.
2. 행이 있고 만료되었으면 2.3대로 처리하고 401.
3. 행이 있고 유효하면:
   - 세션을 만들지 않는다.
   - 실패 횟수를 0으로 한다(비밀번호는 맞았으므로).
   - 이전 `password_change` 토큰을 무효로 하고 새 토큰을 발급한다(유효 10분, 일회용).
   - 응답 403, 문제 상세에 `code: "password_change_required"`, `changeToken: "…"`, 제목 "새 비밀번호를 정해야 합니다."

### 4.2 `POST /auth/password-change` (새)

본문 `{ "token", "newPassword" }`. 로그인처럼 IP별 요청 제한을 둔다.

1. 토큰 확인(`password_change`). 없거나 만료면 410 "시간이 지났습니다. 임시 비밀번호로 다시 로그인하세요."
2. `PasswordPolicy.check("newPassword", …)`.
3. 새 비밀번호가 지금 해시와 맞으면(임시 비밀번호와 같으면) 422 `newPassword` "임시 비밀번호와 다른 비밀번호를 정하세요."
4. `password_hash` 저장, `temporary_passwords` 행 삭제, `last_login_at` 갱신, `password_change` 토큰 무효.
5. 그 사람의 다른 세션을 모두 끝내고 로그인시킨다(`signIn`). 응답은 `Me`(초대 수락과 같은 모양).

### 4.3 SSO

임시 비밀번호가 남아 있어도 SSO 로그인은 그대로 된다. 변경 강제는 비밀번호 로그인에만 적용한다. 임시 비밀번호는 기한이 지나면 쓸 수 없게 된다(2.3).

## 5. 화면

### 5.1 관리 · 사용자 (`frontend/src/pages/admin/users.tsx`)

- 위쪽 버튼 **사용자 초대** → **사용자 추가**. 대화상자 제목도 **사용자 추가**.
- 대화상자에 '등록 방법' 라디오:
  - **초대 메일 보내기**(기본): 지금과 같음. 확인 버튼 "초대 보내기".
  - **임시 비밀번호 만들기**: 확인 버튼 "만들기". 만들면 결과 대화상자(5.2)를 연다.
- 행 메뉴:
  - **임시 비밀번호 발급**: 대상이 `active` 또는 `invited`이고, 나 자신이 아니고, 대상이 관리자이면 내가 관리자일 때. 먼저 확인 대화상자 "○○님의 비밀번호를 임시 비밀번호로 바꿉니다. 로그인된 곳에서 모두 로그아웃됩니다." → 결과 대화상자.
  - **임시 비밀번호 보기**: 같은 조건에 더해 `temporaryPasswordUntil`이 있을 때. 3.3을 불러 결과 대화상자.
- 상태 칸: 일시 잠김처럼 배지 **임시 비밀번호**와 "○○까지". 기한이 지났으면 경고색 **임시 비밀번호 만료**.

### 5.2 결과 대화상자 '임시 비밀번호'

- 이메일, 임시 비밀번호(고정폭, **복사** 버튼), "○○까지 유효", 발급한 사람·시각(보기일 때).
- 안내: "사용자가 처음 로그인할 때 새 비밀번호를 정합니다. 새 비밀번호를 정하면 이 비밀번호는 더 볼 수 없습니다."
- **전달용 문구 복사**: 아래 문구를 클립보드에 넣는다(접속 주소는 `window.location.origin` + `/login`).

  ```
  [openPMS] 계정이 준비되었습니다.
  접속 주소: http://…/login
  이메일: hong@…
  임시 비밀번호: …
  유효 기한: 2026.10.19 14:00까지
  처음 로그인하면 새 비밀번호를 정합니다.
  ```

- 비밀번호는 토스트·목록·주소창에 띄우지 않는다. 대화상자를 닫으면 화면 상태에서 지운다.
- 복사 버튼에 접근 가능한 이름, "복사했습니다"는 라이브 영역으로 알린다. 초점 처리는 기존 대화상자와 같다.

### 5.3 로그인 (`frontend/src/pages/login.tsx`)

- 로그인 응답이 `password_change_required`이면 같은 화면(`AuthShell`)이 **새 비밀번호 정하기** 폼으로 바뀐다. `auth-links.tsx`의 `NewPasswordFields`(새 비밀번호·확인, 규칙 안내)를 재사용한다.
- 변경 토큰은 컴포넌트 상태에만 둔다. 별도 주소(route)를 만들지 않는다.
- 저장하면 4.2로 로그인되고 `next` 또는 홈으로 간다.
- 410이면 "시간이 지났습니다. 임시 비밀번호로 다시 로그인하세요."를 보이고 로그인 폼으로 돌아간다.
- 만료된 임시 비밀번호(401)는 서버 문구를 그대로 보인다.

### 5.4 함께 맞출 것

- 가짜 데이터 계층(`frontend/src/api/fake`): 3·4절과 같은 규칙(권한, 거절, 만료, 세션 종료, 보기). 사용자 시드 모양이 바뀌면 `db.ts`의 `SCHEMA`를 올린다.
- 문구는 `frontend/src/i18n/ko.ts`.
- 앱 도움말 `frontend/src/features/help/topics.ts`가 새 매뉴얼 절(7절)을 가리키게 한다.

## 6. 테스트

### 6.1 JUnit `auth/TemporaryPasswordIT` (새)

1. 임시 비밀번호로 만들기: 201, `active`, 비밀번호가 정책 통과, `no-store`, 메일 없음, `Idempotency-Key`를 붙여도 `idempotency_keys`에 저장 안 됨.
2. 첫 로그인: 403 `password_change_required`와 토큰, 세션 쿠키 없음 → 변경하면 `Me`와 세션, 행 삭제, 이후 임시 비밀번호 로그인 실패, 토큰 재사용 410, 다른 세션 종료.
3. 새 비밀번호가 임시와 같으면 422, 정책 위반 422.
4. 만료: 임시 비밀번호 만료 401과 `password_hash` null, 변경 토큰 만료 410.
5. 다시 발급: `invited` → `active`와 초대 링크 무효, 대상 세션 종료, 실패 잠금 해제, 재설정 토큰 무효, 행 덮어쓰기.
6. 보기: 같은 비밀번호, 권한(사용자 관리자 → 관리자 대상 403), 나 자신 422, 만료·변경 뒤 404.
7. 거절: 권한 없음 403, 잠김 422, 삭제 404.
8. 다른 경로에서도 행 삭제: 재설정 링크, 초대 수락, 본인 변경.
9. 정리 작업: 만료 행 삭제와 `password_hash` null.
10. `OidcIT`에 1건: 임시 비밀번호가 있어도 SSO 로그인 됨.

### 6.2 e2e `frontend/e2e/f19-temporary-password.spec.ts` (새)

- F19-T2: 초대됨 사용자에게 행 메뉴로 다시 발급 → **임시 비밀번호 보기**가 같은 값 → 로그인과 변경 → 보기 메뉴가 사라짐.
- F19-T3: 사용자 관리자에게는 관리자 행에 발급·보기 메뉴가 없다.
- `a11y.spec.ts`: 사용자 추가 대화상자, 결과 대화상자, 새 비밀번호 정하기 폼.
- **사용자 초대** 버튼을 누르는 기존 e2e는 **사용자 추가**로 고친다.
- 가짜 계층(5173)은 손으로 한 번 확인한다.
