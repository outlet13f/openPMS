받는 것

1: 장애(service_tickets)

넘겨주는 것

알려진 오류·임시 해결책 → 6(문서로 만들기). 장애·문제에서 변경 만들기 → 5

문제 상태 흐름

등록→분석 중→알려진 오류→해결→종료
문제 해결→연결된 장애 일괄 해결 (처리자가 고름)

같은 원인으로 되풀이되는 장애를 문제로 묶어 근본 원인을 찾고, 해결 전까지 쓸 임시 해결책과 알려진 오류를 남겨 처리자가 다음 장애를 빨리 처리하게 한다. 문제가 해결되면 묶인 장애를 한 번에 정리한다.

합의한 것

항목 결정
저장 문제 = 작업 패키지 유형 "문제" + 1:1 확장 problem_records
장애와의 연결 장애 하나는 문제 하나에만 묶인다(service_tickets.problem_id). 일반 관계(relations)는 쓰지 않는다
문제 해결 시 묶인 미해결 장애 목록을 처리자에게 보여 주고, 처리자가 골라서 한 번에 해결 처리한다(요청자에게 알림)
보기 권한 문제는 처리자 전용. 요청자 포털에는 보이지 않는다

범위 밖

  • 장애를 자동으로 묶는 규칙(같은 CI·같은 시간대 등). 4단계 CMDB 뒤에 다시 본다
  • 근본 원인 분석 양식(5 Whys, 피시본 등)의 구조화. 서식 있는 텍스트로 쓴다
  • 문제의 SLA

2데이터 (마이그레이션 V22 problem_management.sql, 개발 데이터 V1006)

  • 유형 "문제"와 상태 "등록 → 분석 중 → 알려진 오류 → 해결 → 종료"를 더하고 워크플로를 잇는다. "해결"·"종료"는 is_closed
  • problem_records (작업 패키지와 1:1)
    • work_package_id PK, FK on delete cascade
    • root_cause_html, root_cause_text
    • workaround_html, workaround_text
    • known_error boolean not null default false, known_error_at timestamptz
    • resolved_at timestamptz
    • 인덱스: workaround_text·root_cause_text에 gin_trgm_ops(처리자 검색), (known_error) where known_error
  • service_tickets에 problem_id uuid references work_packages (id) on delete set null과 인덱스를 더한다. 앱에서 대상이 "문제" 유형이고 같은 서비스 데스크 프로젝트인지 확인한다
  • known_error를 켜면 상태를 "알려진 오류"로, 끄면 "분석 중"으로 맞춘다(같은 트랜잭션)

3동작 (com.openpms.itsm.Problems)

묶기

  • 장애 상세의 "문제에 연결": 기존 문제를 찾아 고르거나 "새 문제 만들기"(제목·설명을 장애에서 채움). 저널 양쪽에 남긴다
  • 문제 상세의 "장애 연결": 미해결 장애를 여러 개 골라 한 번에 묶는다
  • 이미 다른 문제에 묶인 장애는 옮길지 확인한다

알려진 오류와 임시 해결책

  • 장애를 접수·처리할 때 제목으로 알려진 오류를 찾아(similarity, 상위 5개) 처리자 화면 옆에 "비슷한 알려진 오류"로 보여 준다. 고르면 그 문제에 묶고 임시 해결책을 답변 초안에 넣는다(보내기 전에 처리자가 고친다)
  • 임시 해결책을 요청자에게 그대로 보여 주지 않는다. 처리자가 고른 내용만 공개 코멘트로 나간다. 6단계에서 알려진 오류를 지식 베이스 문서로 만드는 기능을 더한다

문제 해결

  • 문제가 "해결"이 되면 resolved_at을 기록하고, 처리자에게 "연결된 장애 일괄 해결" 대화상자를 연다(묶인 미해결 장애, 기본은 모두 선택)
  • 확인하면 고른 장애들을 해결 상태로 바꾸고, 공통 해결 메모(처리자가 쓴 공개 코멘트)를 각 장애에 남긴다. 각 장애마다 워크플로·권한을 검사하고 실패한 건은 결과 목록에 이유와 함께 보여 준다(일부만 성공 가능)
  • 일괄 처리는 장애마다 별도 트랜잭션으로 한다. 한 건의 실패가 나머지를 되돌리지 않고, 긴 트랜잭션으로 잠금을 오래 잡지 않는다
  • 처리자가 대화상자를 닫으면 아무것도 바꾸지 않는다. 나중에 문제 상세에서 다시 열 수 있다

4화면

  • 작업 패키지 상세(문제): 근본 원인, 임시 해결책, 알려진 오류 토글, "연결된 장애" 표(번호, 제목, 요청자, 상태, SLA)
  • 작업 패키지 상세(장애): "문제" 칸(연결·해제), 비슷한 알려진 오류 패널
  • 목록: 열 "문제", "연결된 장애 수", 필터 "알려진 오류", "문제 없음(장애)"
  • 서비스 데스크 대시보드 위젯: 미해결 문제 수, 연결 장애가 많은 문제 상위 5개

5보안

  • 포털 응답에 problem_id와 문제 정보를 넣지 않는다(PortalSecurityIT에 확인 추가)
  • 문제 보기·연결은 view_service_tickets·handle_service_tickets 권한을 그대로 쓴다

6테스트

  • JUnit
    • ProblemsIT: 묶기·옮기기·해제, 다른 프로젝트·다른 유형 거부, 알려진 오류 토글과 상태 맞추기
    • ProblemBulkResolveIT: 일부 실패(워크플로 불가) 시 나머지는 해결, 요청자 알림, SLA resolved_at
    • KnownErrorSearchIT: 비슷한 알려진 오류 순서
    • PerfBudgetIT: 연결 장애가 많은 문제 상세, 비슷한 알려진 오류 검색
  • e2e: 장애 둘을 새 문제로 묶음 → 임시 해결책 기록·알려진 오류 → 새 장애 접수 시 추천에서 골라 묶음 → 문제 해결 → 일괄 해결 → 요청자 포털에 해결 표시
  • 가짜 데이터 계층에 같은 규칙, SCHEMA 올림

7문서

01·02, 04(문제 API, 일괄 해결), 05(V22), 06, 07(새 절: 문제 관리), 08·09. 도움말 연결.

8위험과 대응

위험 대응
일괄 해결이 많은 장애를 한 번에 바꿔 느려짐 장애마다 트랜잭션을 나누고 상한(한 번에 200건)
임시 해결책의 내부 정보가 요청자에게 샘 자동 공개 없음, 처리자가 고친 초안만 공개 코멘트로
비슷한 오류 검색이 목록을 느리게 함 상세 화면에서만 따로 불러오고 trgm 인덱스 사용
