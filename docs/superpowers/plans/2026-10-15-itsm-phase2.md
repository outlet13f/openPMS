# ITSM 2단계(서비스 카탈로그·승인) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 직원이 포털에서 서비스 항목(카탈로그)을 골라 항목별 양식으로 요청하고, 요청자의 관리자·처리 그룹 책임자의 단계별 승인을 거친 뒤 처리 그룹에 접수되게 한다. 승인자는 멤버가 아니어도 포털의 "내 승인함"에서 승인·반려한다.

**Architecture:** 1단계 틀을 그대로 쓴다. 카탈로그는 서비스 데스크 프로젝트의 설정(`catalog_*` 테이블), 요청은 1단계 티켓(작업 패키지 + `service_tickets.catalog_item_id`), 승인은 `ticket_approvals`(요청마다 만든 승인 행)다. 새 클래스 `itsm/Approvals`(승인자 정하기는 순수 함수), `itsm/ServiceCatalog`(카탈로그 설정), `itsm/ApprovalController`(포털 승인함, 승인자 본인만), `itsm/ApprovalMail`(승인 요청·지연 알림 메일)을 더한다. 승인으로 상태가 바뀌는 것은 작업 패키지 저장 경로의 새 진입점 `Acting.APPROVAL`이 맡는다.

**Tech Stack:** Spring Boot 4 / Java 21(가상 스레드) / jOOQ / Flyway / PostgreSQL 17 / db-scheduler, React 19 / Vite / TypeScript / TanStack Query / Tailwind v4, JUnit 5 + MockMvc, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-14-itsm-phase2-catalog-design.md` (1단계 `2026-10-14-itsm-design.md`, 계획 `docs/superpowers/plans/2026-10-14-itsm-phase1.md`)

## 설계서 보완 (1단계 구현에 맞춰 정함, Task 1에서 설계서에도 적음)

1. **승인으로 바뀌는 상태:** 승인자는 멤버도 요청자도 아니어서 워크플로에 걸리지 않는다. `WorkPackageService`에 `Acting.APPROVAL`을 더해, "승인 대기"에서 "접수"(마지막 승인) 또는 "반려"(반려)로만 바꾸게 한다. 저널의 작성자는 결정한 승인자다.
2. **승인 행의 상태:** 설계서의 `pending | approved | rejected | skipped`에 `waiting`(아직 차례가 오지 않은 뒷단계)을 더한다. 내 승인함에는 `pending`만 보인다. 한 단계가 끝나면 다음 단계의 `waiting`이 `pending`이 된다.
3. **승인 행의 키:** 승인자가 없어 건너뛴 행은 `approver_id`가 비므로, unique는 `(work_package_id, step_no, approver_kind)`로 한다. 한 단계의 두 종류가 같은 사람이면 둘째는 `skipped`(중복).
4. **승인자에게 알리기:** 승인자는 멤버가 아닐 수 있어 알림 센터를 못 쓴다. 새 메일 작업 `approval-mail`(1분)이 차례가 온 승인자에게 메일을 보내고(`ticket_approvals.notified_at`), 3근무일이 지나도 결정이 없으면 한 번 더 보낸다(`reminded_at`). 처리자 목록에는 "승인 지연" 필터로 보인다. 요청자는 1단계 `portal-mail`로 결과(접수·반려 상태 변경)를 받는다.
5. **처리자가 승인을 건너뛰지 못함:** 처리자 역할의 워크플로는 "승인 대기"에서 "취소"로만 갈 수 있다. "승인 대기"에서 다른 경로(취소, 관리자의 직접 변경)로 나가면 남은 `pending`·`waiting` 행은 `skipped`가 되고 저널에 남는다.
6. **항목 양식의 필수:** 항목 양식의 필드는 `custom_fields.portal_visible`과 관계없이 그 항목 요청에 보이고, 필수 여부는 `catalog_item_fields.is_required`로 포털 서비스가 검사한다. 항목에 없는 필드는 1단계 규칙대로 포털 요청에서 필수 검사를 하지 않는다.
7. **반려 사유:** 반려 사유(필수)는 승인자 이름으로 된 공개 코멘트로 남아 요청자가 포털에서 본다. 승인할 때의 의견(선택)은 `ticket_approvals.comment`에만 남고 처리자 승인 패널에서 보인다.

```java
package com.openpms.itsm;

import java.util.ArrayList;
import java.util.Comparator;
import java.util.List;
import java.util.Objects;
import java.util.UUID;

/**
 * Approvals of a catalog request (docs/superpowers/specs/2026-10-14-itsm-phase2-catalog-design.md §3): steps in order,
 * anyone of a step decides it, one rejection ends the request.
 */
public class Approvals {
    public static final String MANAGER = "requester_manager";
    public static final String GROUP_LEAD = "group_lead";

    public record StepRule(int stepNo, String kind) {}

    public record Planned(int stepNo, String kind, UUID approverId, String decision, String skipReason) {}

    private static final List<String> KIND_ORDER = List.of(MANAGER, GROUP_LEAD);

    /** The rows to create for a new request. Pure: the caller looks up the manager and the group lead. */
    public static List<Planned> plan(List<StepRule> rules, UUID requesterId, UUID managerId, UUID groupLeadId) {
        var sorted = new ArrayList<>(rules);
        sorted.sort(Comparator.comparingInt(StepRule::stepNo).thenComparingInt(r -> KIND_ORDER.indexOf(r.kind())));
        var out = new ArrayList<Planned>();
        Integer current = null;
        for (int i = 0; i < sorted.size(); i++) {
            var r = sorted.get(i);
            var who = MANAGER.equals(r.kind()) ? managerId : groupLeadId;
            String skip = null;
            if (who == null) skip = "no_approver";
            else if (who.equals(requesterId)) skip = "requester";
            else {
                for (var earlier : out) {
                    if (earlier.stepNo() == r.stepNo() && earlier.skipReason() == null && Objects.equals(earlier.approverId(), who)) skip = "duplicate";
                }
            }
            if (skip != null) {
                out.add(new Planned(r.stepNo(), r.kind(), skip.equals("no_approver") ? null : who, "skipped", skip));
                continue;
            }
            if (current == null) current = r.stepNo();
            out.add(new Planned(r.stepNo(), r.kind(), who, r.stepNo() == current ? "pending" : "waiting", null));
        }
        return out;
    }

    public static boolean needsApproval(List<Planned> planned) {
        return planned.stream().anyMatch(p -> "pending".equals(p.decision()));
    }
}
```

주의: `skipped` 행에서 `requester`·`duplicate`는 승인자 ID를 남긴다(누구라서 건너뛰었는지 저널·패널에 보이게). `no_approver`만 비운다.

```java
    @Transactional
    public String decide(Ctx ctx, UUID approvalId, boolean approve, String comment) {
        var row = db.selectFrom(TICKET_APPROVALS).where(TICKET_APPROVALS.ID.eq(approvalId), TICKET_APPROVALS.APPROVER_ID.eq(ctx.userId())).fetchOne();
        // not mine, not my turn yet (waiting) or no longer mine to decide (skipped): the same 404
        if (row == null || row.getDecision().equals("waiting") || row.getDecision().equals("skipped")) throw ApiException.notFound(NOT_FOUND);
        if (!approve && Html.text(Html.sanitize(comment == null ? "" : comment)).isBlank()) throw ApiException.field("comment", "반려 사유를 입력하세요.");
        int won = db.update(TICKET_APPROVALS).set(TICKET_APPROVALS.DECISION, approve ? "approved" : "rejected")
                .set(TICKET_APPROVALS.DECIDED_AT, OffsetDateTime.now()).set(TICKET_APPROVALS.COMMENT, approve && comment != null ? comment.trim() : "")
                .where(TICKET_APPROVALS.ID.eq(approvalId), TICKET_APPROVALS.APPROVER_ID.eq(ctx.userId()), TICKET_APPROVALS.DECISION.eq("pending")).execute();
        if (won == 0) throw ApiException.conflict("이미 처리된 승인입니다.", "승인함을 새로 고치세요.", null);
        var f = found(row.getWorkPackageId());   // WorkPackageService.Found built from the row and its project (no visibility check: the approver is not a member)
        var name = Refs.user(ctx.s(), ctx.userId()).name();
        approvals.journal(ctx, f.wp(), approvalId, row.getStepNo() + "단계 " + name + (approve ? " 승인" : " 반려"));
        if (!approve) {
            approvals.skipRemaining(ctx, f.wp());
            workPackages.commentForApproval(ctx, f, comment);
            workPackages.statusForApproval(ctx, reload(f), ItsmIds.STATUS_REJECTED);
            return "rejected";
        }
        // anyone of the step decides it: the others of the step are done, the next step's waiting rows become pending
        db.update(TICKET_APPROVALS).set(TICKET_APPROVALS.DECISION, "skipped").set(TICKET_APPROVALS.SKIP_REASON, "step_done")
                .where(TICKET_APPROVALS.WORK_PACKAGE_ID.eq(row.getWorkPackageId()), TICKET_APPROVALS.STEP_NO.eq(row.getStepNo()), TICKET_APPROVALS.DECISION.eq("pending")).execute();
        var next = db.select(DSL.min(TICKET_APPROVALS.STEP_NO)).from(TICKET_APPROVALS)
                .where(TICKET_APPROVALS.WORK_PACKAGE_ID.eq(row.getWorkPackageId()), TICKET_APPROVALS.DECISION.eq("waiting")).fetchOne(0, Short.class);
        if (next != null) {
            db.update(TICKET_APPROVALS).set(TICKET_APPROVALS.DECISION, "pending")
                    .where(TICKET_APPROVALS.WORK_PACKAGE_ID.eq(row.getWorkPackageId()), TICKET_APPROVALS.STEP_NO.eq(next), TICKET_APPROVALS.DECISION.eq("waiting")).execute();
            return "approved";
        }
        workPackages.statusForApproval(ctx, reload(f), ItsmIds.STATUS_RECEIVED);
        return "approved";
    }
```
