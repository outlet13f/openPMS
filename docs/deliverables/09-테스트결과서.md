### 3.2 E2E 테스트 (Playwright + axe)

- 실행: API(:8090) + `npm run dev:api`(:5174) + 테스트 IdP 컨테이너, `npm run e2e`.
- 결과(1.2, 2026-10-11, 31e39bd): **84/84 통과**. 진행 경과: 384a2f9에서 84/84 → 중간 수정본(합계 규칙 변경 직후)에서 82/84(F00-S4는 토스트 문구가 알림 영역에도 있어 선택자가 2개를 잡은 테스트 문제, F03-G2는 보기 메뉴 연속 변경이 앞 변경을 덮은 BUG-011) → 두 가지를 고친 31e39bd에서 84/84. F03 두 파일을 반복 실행(18회 중 1회 실패, 실패는 f03-views와 섞어 돌릴 때 파일 사이 데이터가 남은 경우로 보임)한 뒤 F03-grouping만 20회 연속 통과. 81053e7(계정 설정 비밀번호 영역의 훅 순서 수정) 뒤 계정 설정을 거치는 a11y·F00-SSO 33건을 다시 돌려 통과. 마지막으로 90006c2(Podman 신뢰 범위) 코드에서 전체 회귀를 다시 돌려 JUnit 62/62, E2E는 첫 실행 83/84(F11-E2의 토스트 문구를 알림 영역도 잡은 테스트 선택자 문제, 앱 결함 아님)였고 선택자를 고친 뒤 84/84. 모든 테스트에서 콘솔 오류·5xx 응답 0건, 거친 화면의 axe(WCAG 2.1 A/AA) 위반 0건. 1.2에서 F11-E2(일시 잠김)를 더했고, F00-S4(비밀번호 없는 계정의 계정 설정)를 보강했으며, F03-G1·G2는 저장된 보기를 받아 온 뒤 보기 메뉴를 바꾸도록 고쳤습니다.

### 7.2 출시 판정

**판정: 출시 가능 (사내 운영 배포 승인 권고, 아래 조건 포함)**

판정 근거:
- 계획서의 종료 기준을 모두 충족했습니다.
- 테스트와 점검 중 발견한 결함 13건(BUG 11건, 배포 2건)을 모두 고쳤고 열린 결함이 없습니다. 1.2 점검에서 찾은 S2 결함(BUG-008, 프록시 뒤 요청 제한)도 고쳤고(Podman 구성은 90006c2), 고친 운영 이미지로 게시 포트를 거쳐 확인했습니다(3.4.3). 실제 사내 프록시에서의 확인을 배포 조건에 넣었습니다.
- 1.0 이후 넣은 세 기능(목록 그룹화·합계, 보드 보강, 날짜·시간 형식)을 포함해 JUnit·E2E 전체 회귀를 다시 통과했고, 새 케이스 13건(JUnit 7, E2E 6)을 더했습니다. 1.2 보완(384a2f9, 31e39bd) 뒤에도 전체 회귀(JUnit 62/62, E2E 84/84)를 통과했고 새 케이스 5건(JUnit 4, E2E 1)을 더했습니다.
- 1.0의 배포 조건 1("SSO가 포함된 이미지로 배포 스모크를 다시 함")은 2026-10-11 최신 이미지 재검증(3.4.2: 마이그레이션 V1–V10, 헬스 `UP`, SSO 공개 응답, 브라우저 핵심 흐름)으로 충족되어 조건에서 뺐습니다.
- 접근성 자동 검사를 통과했고(WCAG 2.1 A/AA), 데이터 격리·CSRF·잠금·SSO 위조 방지 같은 보안 관련 동작을 자동 테스트로 확인했습니다.

배포 때 지켜야 할 조건:
1. 사내 SMTP로 초대 메일이 실제로 도착하는지 확인합니다(OI-08).
2. 사내 SSO를 쓸 경우, `replica/deploy.md` "사내 SSO 연결" 순서대로 실제 IdP와 연결을 시험한 뒤 사용자에게 공개합니다(OI-07).
3. 사내 리버스 프록시가 `X-Forwarded-For`·`X-Forwarded-Proto`를 넘기는지, 프록시 주소가 앱의 신뢰 범위(기본: 이 호스트, Docker 172.16–31.x, Podman 10.88–89.x) 안인지 확인하고, 두 PC에서 로그인해 요청 제한이 사람마다 걸리는지 봅니다(M-06, OI-14). 운영 이미지 자체의 헤더 처리는 3.4.3에서 확인했으므로 남은 것은 사내 프록시와 네트워크 구성입니다.
4. 운영 서버에 배포한 뒤에는 운영자 매뉴얼의 설치 절차대로 헬스 `UP`과 로그인을 확인합니다(일반 설치 확인. 1.1 기능까지의 이미지 검증은 3.4.2로, 1.2 보완이 든 이미지(90006c2) 검증은 3.4.3으로 끝남).
5. 미결 항목(5장)은 출시를 막지 않는 항목으로 보고, 다음 단계에서 처리합니다.

(1.0의 조건 "운영 배포 직후 SSO가 포함된 이미지로 배포 스모크를 다시 함"은 3.4.2로 해소되었습니다.)
