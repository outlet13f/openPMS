## 1. 개요

### 1.1 목적

이 문서는 openPMS의 테스트 범위, 전략, 환경, 기준, 테스트 케이스를 정의합니다. 이 계획에 따라 수행한 결과는 「09-테스트결과서」에 적습니다.

### 1.2 배경

openPMS는 OpenProject 17.9.1의 화면과 동작을 사내용으로 다시 만든 프로젝트 관리 시스템입니다. 원본 소스 코드는 읽거나 옮기지 않았습니다(클린룸). 테스트도 원본 인스턴스에는 어떤 자동 요청도 보내지 않고, openPMS 자체의 화면과 API만 대상으로 합니다.

### 1.3 용어

| 용어 | 뜻 |
| --- | --- |
| 흐름(F00–F16) | 사용자 업무 흐름 단위. 예: F01 작업 패키지 만들기. F12(여러 작업 한꺼번에 바꾸기)는 1.3에서, F13(키보드 단축키)·F14(내보내기)·F15(API 토큰·웹훅)는 1.4에서, F16(시간 기록)은 1.6에서 붙인 번호로 recon에는 없음 |
| 화면(S01–S37, X01–X11) | 화면 목록의 화면 번호. 예: S06 작업 목록. recon에 없는 화면은 06-화면설계서의 X-ID(1.6의 X10 내 공수, X11 공수 보고서 등) |
| 복원 지점(restore point) | 시드 데이터를 넣은 DB의 사본(`openpms_seed`). 테스트는 이 사본에서 시작합니다 |
| axe | 웹 접근성 자동 검사 도구(axe-core). WCAG 2.1 A/AA 규칙으로 검사합니다 |
| 테스트 IdP | SSO 테스트용 OpenID Connect 공급자(`frontend/e2e/fake-idp.mjs`). 운영용이 아닙니다 |
| 점검 묶음 | 개발 세션 중 작성·실행한 브라우저 점검 스크립트 27묶음. 저장소에는 아직 없습니다 |

## 2. 테스트 대상과 범위

### 2.1 대상

| 구분 | 대상 | 위치 |
| --- | --- | --- |
| 프런트엔드 | React + Vite + TypeScript 단일 페이지 앱 | `frontend/` |
| 백엔드 | Spring Boot 4 + jOOQ, REST API `/api/v1` | `backend/` |
| DB | PostgreSQL 17, Flyway 마이그레이션 V1–V17(1.4에서 V11–V15, 1.5에서 V16 `idempotency_keys`, 1.6에서 V17 `time_entries`·`time_activities`) | `backend/src/main/resources/db/migration` |
| 배포 | 이미지 1개(SPA + API) + PostgreSQL 17, compose | `Dockerfile`, `compose.yaml`, `.env.example` |

### 2.2 범위에 넣는 기능

로그인(폼·사내 SSO, 로그인 실패 잠금과 관리자 해제, 리버스 프록시 뒤 요청 제한, SSO 사용자의 비밀번호 만들기), 작업 패키지 생성·수정·상태 전환, 보기 저장·공유, 목록 그룹화·합계, 일정(근무일·선후행·Gantt), 관계·계층, 보드(빈 보드, 열에서 만들기, 보드 필터 포함), 코멘트·멘션·알림(이유별·프로젝트별 필터 포함), 프로젝트·멤버(템플릿에서 만들기, 상위 프로젝트), 일괄 편집(행 우클릭 메뉴, 일괄 복사), 날짜 대화상자의 선행·후속·하위 탭, Gantt 막대 그리기, 하위 프로젝트별·상위-하위 보드, (1.4) 활동 거르기·정렬과 내부 코멘트, 권한 보고서, Gantt 라벨, 키보드 단축키, 목록 강조 표시·기준선, 프로젝트 복사, 고대비 테마, 개요 위젯, PDF 내보내기, API 토큰·OpenAPI·API 문서, 웹훅(서명·재시도·테스트 전송), (1.5) 기준선의 빠진 작업, 생성 요청 중복 방지(`Idempotency-Key`), 웹훅 이벤트 범위와 사내망 주소 막기, 서버 쪽 알림 필터·건수, 관리(유형·상태·워크플로·우선순위·사용자 정의 필드·진행률·사용자(전역 역할 배정)·그룹·역할·로그인 정책·달력과 날짜(근무일·날짜 형식)), 내보내기, 공유, 예약 작업(날짜 알림·메일), 접근성, 배포. (1.6) 시간 기록: 내 공수 주간 입력표(키보드 입력·Ctrl+S·`1:30`, 하루 근무 시간 초과 경고, 전부 아니면 전무 저장), 작업의 시간 탭, 공수 보고서와 Excel, 시간 기록 활동, 하루 24시간 제한, 시간 기록 권한과 모듈. (1.7) 템플릿에서 만들기·프로젝트 복사의 **새 시작일**(근무일 기준 일정 이동, 버전은 달력일 이동, 날짜가 아닌 값 422).

### 2.3 범위에서 빼는 것

- 원본에서 범위 밖으로 정한 모듈: 비용·예산(1.6부터 시간 추적은 범위 안), 미팅, 위키, 뉴스, 문서, 포럼, 백로그, 포트폴리오, BIM, 리포지토리 연동, 외부 파일 저장소, LDAP·SAML·SCIM 등(`replica/parity.md` "일부러 뺀 것").
- 결제: 사내 도구라 결제 기능이 없습니다.
- 성능·부하 테스트: 이번 단계 범위가 아닙니다(10장 위험 참고).

### 3.1 단위·통합 테스트 (JUnit)

- 위치: `backend/src/test/java/**` (32개 클래스, 92개 테스트 메서드). 1.7에서 `TemplatesIT`에 1건(3 → 4, 새 시작일)을 더했습니다. 1.6에서 `TimeEntriesIT`(4)를 새로 만들었습니다. 1.5에서 `IdempotencyIT`(1), `NotificationFiltersIT`(1)를 새로 만들고 `WebhooksIT`에 4건, `BoardsIT`에 2건, `BaselineIT`·`ApiTokensIT`·`OidcIT`·`TemplatesIT`에 1건씩 더했습니다. 1.4에서 `InternalCommentsIT`(1), `ApiTokensIT`(1), `BaselineIT`(1), `WebhooksIT`(1)를 새로 만들고 `TemplatesIT`·`ProjectHierarchyIT`·`ExportIT`에 1건씩 더했습니다. 1.1에서 `GroupingIT`(3), `BoardsIT`(3), `DisplaySettingsIT`(1)를, 1.2에서 `LockoutIT`(1), `ClientAddressIT`(1), `DisplayFormatsReloadIT`(1)와 `GroupingIT` 1건(3 → 4)을, 1.3에서 `TemplatesIT`(1), `GlobalRolesIT`(1), `ProjectHierarchyIT`(1)와 `BoardsIT` 2건(3 → 5), `TransfersIT` 1건(3 → 4)을 더했습니다.
- 실행: `backend/scripts/dev.sh test`. 복원 지점(`openpms_seed`)을 템플릿으로 버리는 DB `openpms_test`를 새로 만들고, 그 DB에 대해 JDK 21 컨테이너에서 `./gradlew test`를 실행합니다. 개발 DB는 건드리지 않습니다.
- 사전 준비: 복원 지점을 한 번 만들어 둡니다(`dev.sh snapshot-db`, 앱 정지 상태).
- `*Test`(예: `ScheduleTest`, `ProgressTest`, `FileStorageTest`)는 DB 없이 도는 순수 단위 테스트이고, `*IT`는 Spring 컨텍스트와 DB를 쓰는 통합 테스트입니다.
- 테스트가 시드 계정의 비밀번호나 설정을 바꾸면 `finally`에서 되돌립니다.

(1.5) `IdempotencyIT`는 만든 작업과 `idempotency_keys`를 지우고, `NotificationFiltersIT`는 김서연의 알림을 미리 보관했다가 601건을 넣어 시험한 뒤 원래 알림으로 되돌립니다. `BaselineIT`·`WebhooksIT`·`BoardsIT`·`TemplatesIT`의 새 케이스는 바꾼 우선순위·만든 작업·보드·하위 프로젝트·복사본·웹훅·토큰을 `finally`·`cleanUp`에서 정리하고, `OidcIT` 새 케이스는 만든 시험 계정을 정리합니다. `WebhooksIT`의 받는 쪽 서버는 `/redirect`이면 302를 돌려줍니다. e2e F03-B3는 #12의 우선순위를 긴급으로 바꾼 채 두고, F11-N2는 만든 전역 역할과 배정을 `finally`에서 지웁니다(다음 스펙 전에 DB도 복원). (1.7) `TemplatesIT`의 새 시작일 케이스는 만든 복사본(copied-project)을 테스트 안에서 지우고, e2e F10-H6은 복사본(web-platform-2027)을 둔 채 끝나며 다음 스펙 전에 DB가 복원됩니다.
- 공통 실패 조건(`frontend/e2e/support.ts`): 테스트 중 브라우저 콘솔 오류, 페이지 예외, 5xx 응답이 하나라도 있으면 그 테스트는 실패입니다. 테스트가 일부러 일으킨 4xx만 예외입니다.

### 8.2 E2E 화면별 접근성 테스트 (`a11y.spec.ts`, 34건)
